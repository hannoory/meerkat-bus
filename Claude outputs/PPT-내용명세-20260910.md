## 4장 · 여정 — 가설과 두 번의 벽

**들어갈 것 — 가로 타임라인 한 줄**
```
[가설]              [벽 ①]                [벽 ②]                    [지금]
엔진 + 설정      →  입력 양식을         →  단어 목록이 1만 줄    →  순서를 뒤집었다
판정=코드           아무도 안 쓴다         (끝나지 않는 목록)         AI가 읽고 코드가 검사
말=AI
```
- 아래 작은 글씨: **「단어를 목록에 더해서 증상을 없애지 마라」**
- 가능하면 단어 목록 줄 수가 늘어나는 곡선을 작게

**말하는 것**: 가설은 맞았다(새 분야에 엔진 코드 0줄) → 벽① 입력 양식 → 벽② 단어 목록 1만 줄, **끝이 없다** → 그래서 순서를 뒤집었다 → 규율 하나

**★ 짚을 자리 하나**: **「끝나지 않는 목록이었습니다」**

## 8장 · 숫자 두 개  ★★★ 심장

**들어갈 것**
```
   모델에 맡겼을 때              코드로 옮긴 뒤
   라이브 510회                 정답지 38건
   → 흔들림 29건                → 불일치 0
   [재현성]                     [일치성]
```
- ★★ **「이 둘은 같은 축이 아니다」**를 화면에 명시. 나란히만 놓으면 「그 둘이 같은 실험입니까?」 한 마디에 무너집니다.
- 아래 작게: 2026-08-05 게이트웨이 실측 · 2026-08-29 재현성 측정

**말하는 것**: 처음부터 코드로 뒀다 → 8/5 게이트웨이 실측(온도를 **줄 자리가 없다**) → 질문을 많이 받아서 **8/29에 직접 쟀다** → 510/29 → 코드 쪽은 잴 필요가 없다, 대신 정답을 맞히는지 쟀다 → **판정 엔진을 1에서 2로 올리고 옛 코드와 새 코드를 같은 정답지로 대조 → 불일치 0** → **두 숫자는 다른 것을 잰 것** → 재현되지 않는 판정은 판정이 아니다

**★ 짚을 자리 하나**: **「같은 축이 아닙니다」**

**디자인**: 숫자 두 개가 크게. 대비되게. 축 이름(재현성/일치성)을 반드시 표기.

## 9장 · 배운 것과 남은 것

**들어갈 것 — 좌우 두 칸**

| **배운 것** | **아직 못 한 것 · 다음** |
|---|---|
| **"모른다"에 이름을 준다** — 위반 / 위반 아님 / **검사 대상 아님** | 접수층 **부품은 만들었고, 그 부품을 쓰는 화면이 못 따라왔다** (설계가 아니라 배선) |
| **읽기는 무한 / 검사는 유한** — 자리를 가르는 잣대 | 판정 엔진 1→2 와 접수층을 **깔끔히 잇지 못한 것이 아쉽다** |
| **단어를 더해 증상을 없애지 마라** | **팩 스튜디오** — 규정을 말로 하면 설정 파일도 항목 구조도 AI가 만든다 |

**말하는 것**: 배운 것 셋(「모른다」 예시 = 주택담보대출을 **비운 채 심의를 멈춘다**) → 못 한 것 → **팩 스튜디오** → 마지막: **「AI에게 무엇을 맡기고 무엇을 맡기지 않을지, 저는 감이 아니라 실측으로 정했습니다」**

**★ 짚을 자리 하나**: **「못 한 것을 못 했다고 말하는 칸을 만들었습니다」**

**★ 평가 렌즈에 「성장 가능성 — 실패에서 배운 것」이 있습니다.** 이 장이 **감점 칸이 아니라 배점 칸**입니다.
