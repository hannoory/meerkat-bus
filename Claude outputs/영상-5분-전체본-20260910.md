## 0. 시작 — 오빠가 칠 한 줄

```
bash tools/shoot-prep.sh
```

연금 서버(8787)와 화면(5173)이 뜨고 브라우저가 열립니다(`?intake=kit2` 안 붙습니다).
몇 초 뒤 **"■ 이제 찍으면 된다"** 와 터미널에 붙여넣을 명령 두 줄이 화면에 나옵니다.
서버가 늦게 뜨면 같은 줄을 한 번 더 치세요.

**다 찍은 뒤**: `bash tools/shoot-prep.sh -Down`

### 찍기 전 확인 넷
- 터미널 글꼴 **18pt 이상** (1080p에서 14pt는 안 읽힙니다)
- **알림·메신저 전부 끄기** (화면에 다 나옵니다)
- 브라우저 확대 배율 한 번 시험 촬영해서 정하기
- 주민번호·계좌번호 **입력 금지**

### 녹화 설정 (OBS)
**MP4 · 1920×1080 · 30fps · 「고품질, 중간 파일 크기」** → 5분이면 100MB 안쪽
제출 규격: **5분 이내 · 500MB 이내 · MP4** · 파일명 `[사번]_[성명]_시연영상.mp4`

★ **한 번에 5분을 이어 찍지 마세요.** 아래 여섯 컷을 따로 찍고 나중에 붙입니다.

## 컷 2 · 0:30–2:00 — 터미널, 층 일곱  ★★ 이 영상의 심장

**화면**: 새 터미널. 아래를 **붙여넣기**

```
bun run tools/intake-trace.ts --fixture
```

**보여야 할 것**: 세 분야(연금·대출·충동)가 순서대로 돌면서 **①~⑦층이 한 줄씩** 찍힘.
층 이름 옆 **LLM(노랑) / 코드(청록)** 표시가 보여야 함.

**읽는 말**
> 들어온 문장이 일곱 개 층을 지나갑니다. **층마다 누가 처리했는지가 줄 앞에 찍힙니다.**
>
> **첫째 층, 쪼개기. 여기만 AI입니다.** 한 문장이 두 건으로 갈렸습니다.
> **둘째 층, 나눠 담기. 코드입니다.** 쪼갠 값을 분야가 미리 선언해 둔 항목에 나눠 담습니다.
> **셋째 층, 검사. 코드입니다.** 여기가 이 시스템의 핵심입니다. 항목마다 통과인지 거절인지, 거절이면 **왜 거절인지**가 찍힙니다. 그리고 **거절 이유는 딱 세 가지뿐입니다.** 모양이 안 맞거나, 목록에 없거나, 사용자가 쓴 말과 다르거나.
>
> **읽기는 무한하지만 검사는 유한합니다.** 그래서 시험지로 잠글 수 있습니다.
>
> 보십시오. **"로봇"이 거절됐습니다.** 종목 목록에 그 이름이 없습니다.
>
> **넷째 층, 되묻기.** 여기가 중요합니다. **AI에게 다시 시키지 않고, 사람에게 묻습니다.** "로봇 ETF 말씀이신가요?" 사람이 답하면 **그 항목에만** 정확히 꽂힙니다.
>
> 요즘 말하는 **자기 교정, Self-Correction이 여기 있습니다. 다만 모델 안이 아니라 사람과의 왕복에 뒀습니다.**
>
> **다섯째부터 일곱째 층 — 되짚어 주는 문장도, 화면에 그릴 데이터도 이 부품이 만듭니다.** 화면 코드는 문장을 한 줄도 짓지 않습니다.

★ 층마다 **잠깐 멈추고** 다음 층으로 넘어가세요. 나중에 말을 얹을 때 맞추기 쉽습니다.

## 컷 3 · 2:00–2:50 — 3회 재현  ★★ 결정타

**화면**: 같은 터미널에 이어서 **붙여넣기**

```
bun --env-file=.env --env-file=.env.live run tools/intake-trace.ts --live --repeat 3 --pack pension-kr "반도체 ETF 300만원어치 매도하고, 로봇 200만원 삽니다"
```

**보여야 할 것**: 실행 3회, 끝에 **"★ 3회 실행 요약"** — `[1] 분해` 줄과 `[3]`·`[5]`·봉투 해시 줄

**읽는 말**
> 같은 문장을 **세 번** 넣어 보겠습니다. 실제 모델을 부르는 겁니다.
>
> **보시면 세 번 다 같은 결과가 나왔습니다.** 판정으로 넘어가는 값의 지문까지 같습니다.
>
> 그런데 **이게 보장되는 게 아니라는 걸 저는 실측으로 알고 있습니다.** 같은 방식으로 **오백열 번을 돌려보니 스물아홉 번은 답이 달랐습니다.** 같은 문장, 같은 지시문, 같은 모델인데요.
>
> **오늘 세 번이 같았다는 것과, 언제나 같다는 것은 다릅니다.** 그래서 **읽는 일만 모델에 남기고, 검사와 판정은 코드로 옮겼습니다.** 최신 기법을 안 쓴 게 아니라, **어디에 둘지를 실측으로 정한 것입니다.**

★★ **이 명령은 진짜 모델 호출이라 과금이 붙습니다.** 리허설에서 여러 번 돌리지 말고 **실제 녹화 테이크에서만** 쓰세요.
★ `.env` 와 `.env.live` **둘 다** 겹쳐 넘겨야 합니다. 안 그러면 조용히 건너뛰고 분해가 실패로 찍힙니다.
★ 모델 응답 대기 시간은 편집에서 **잘라내거나 2배속**.

## 컷 4 · 2:50–3:50 — 화면 (연금, v1)

**화면**: `shoot-prep.sh`가 이미 열어 둔 브라우저 탭. **클릭 순서 그대로**

1. `http://localhost:5173/`
2. **"온보딩 — 원칙 5개"** → 「**보유 선언으로**」
3. **"보유 선언"** → 「**예시 채우기**」 → 「**다음**」
4. **"심의 입력"** → 입력창에 **이 문장 그대로**:
   ```
   반도체 ETF를 500만원 추가매수하려고 합니다.
   ```
5. **⊕ "더 보기"** → 「**심의 항목 직접 고치기**」
6. 시트에서: 섹터 **반도체** · 방향 **매수** · 금액(만원) **500** · 자금 출처 **「신규 자금(밖에서 새로 넣는 돈)」**
7. 「**이 값으로**」 → 8. 「**보내기**」 → 9. 확인 카드에서 「**응, 심의해줘**」
10. **"심의 결과"** 가 뜰 때까지 기다림
11. 아래 띠의 미어캣 칩 하나를 눌러 발언을 펼침 → 「**닫기**」 → 결과 화면이 살아 있는 것까지

**읽는 말**
> 이제 화면입니다. 지금 보시는 건 **현재 서비스 중인 화면**입니다.
>
> 문장을 그대로 씁니다. 시스템이 **이해한 것을 먼저 되짚어 주고**, 확인하면 심의로 넘어갑니다.
>
> **일곱이 섭니다.** 시장분석가, 원칙검사관, 과거기록관, 반론자, 의장, 그리고 개회와 동반자입니다. **반론자만 다른 위원들의 말을 읽고 반박합니다.** 전부 대화하게 두면 합의가 생기고, **합의는 곧 추천이 되기 때문입니다.**
>
> 위원을 누르면 그 위원의 말이 펼쳐집니다. **여기 숫자들은 코드가 이미 확정한 값이고, 위원들은 그것을 말로 옮길 뿐입니다.**
>
> 그리고 마지막에 **"그래서 살까요?"라고 물어도 아무도 답하지 않습니다.** 그게 이 제품입니다.

★ 6번을 건너뛰면 시스템이 자금 출처를 채팅으로 되물을 수 있습니다 — **그 경로는 검증하지 않았습니다.** 안전하게 6번을 쓰세요.

## 컷 5 · 3:50–4:30 — 연금 → 대출 전환

**화면**: 아래 순서 그대로 (**서버 재기동 약 6초**, 40초 컷 안에 들어감)

1. 연금 서버 창을 닫습니다 (Ctrl+C 또는 그 창 닫기)
2. 같은 저장소 루트에서:
   ```
   PACK_ID=loan-kr bun run server
   ```
3. **화면(vite, 5173) 창은 그대로 둡니다** — 안 내려도 됩니다
4. 브라우저 탭을 **새로고침(F5)**
5. 대출 화면에서 **이 문장 그대로**:
   ```
   카드론으로 40 새로 빌리려 합니다.
   ```
6. 심의 결과까지 봅니다

**읽는 말**
> 같은 엔진이 다른 분야를 받습니다. **연금, 그리고 대출.**
>
> 새 분야를 열 때 **엔진 코드는 한 줄도 안 고쳤습니다.** 갈린 것은 설정 파일입니다. 대출을 처음 붙였을 땐 열 문항 중 다섯만 맞았는데, **정답지도 판정 엔진도 안 건드리고** 분야 쪽 설정 몇 곳만 고쳐서 열 문항 전부로 올렸습니다.
>
> 세 번째 분야인 충동구매는 **입력받는 데까지는 같은 부품을 쓰지만, 심의는 아직 못 탑니다.** 판정 규격이 다른 세대라서, "사라, 팔라"라는 개념 자체가 없는 분야입니다. **억지로 이으면 지어낸 값이 사용자에게 갑니다. 그래서 잇지 않고 막아 뒀습니다.**

★ **충동구매 화면은 띄우지 마세요.** 말로만 넘깁니다.
★ 서버 재기동 6초는 편집에서 **잘라내세요.**
